# 2026-06-07-Ability标签重构+技能全量树

## 改了什么

1. **删除 `categoryTag`**，功能统合到 `abilityTag`
   - `abilityTag` 移至 `AbilitySO` 基类，主动/被动共用
   - 层级前缀匹配同时实现技能标识和互斥门控
   - `abilityTag.Parent` 决定默认互斥粒度

2. **新增 `extraExclusionTags[]`** 支持跨分类互斥
   - 例：霰弹破门技额外填 `[Ability.Melee]` → 近战动作期间不可用

3. **新增 `OnValidate` 叶标签验证**
   - 扫描全部 GameplayTag 资产，若有子标签则拒绝+清空

4. **新建 `ability-inventory.md`** — 技能全量树
   - 154 技能覆盖 11 个 Skill 标签分类
   - 11 个现实武学流派（拳击/泰拳/八极拳/咏春/太极/柔道/Eskrima/剑道/苗刀/Krav Maga/散打）
   - 远程武器改为射击技术/姿态（弹药决定伤害）
   - 完整 `Ability.*` Tag 树（~110 个叶标签）

5. **远程武器重设计**：龙息弹/膝射等"魔法技"删除，改为抵近射击/屏息精瞄/架枪/火力压制等现实射击技术

## 为什么

- `categoryTag` + `abilityTag` 双 Tag 冗余——层级前缀可同时表达分类和标识
- 叶标签约束保证互斥粒度可控——不会误选父节点导致前缀匹配过宽
- 全量技能树让后续资产创建有明确清单，不再"拍脑袋"

## 已知问题

- 连击链（武学套路）设计完整但延后到 Phase 2+
- 武学套路 tagged 为 Phase 2+，A 测只用武器基础技
- `OnValidate` 扫描全部 Tag 资产在大项目中可能有性能问题（当前 32 个 Tag 无影响）
