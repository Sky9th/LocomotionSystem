# 死亡与存档机制设计

> 日期: 2026-05-23
> 状态: 设计阶段
> 关联: `../game-overview.md` NPC 系统 / `injury.md` 丧尸化

---

## 一、设计目标

死亡是硬核生存的一部分，但 A测阶段不做复杂的继承机制。保持简单：死亡 = 读档。

核心原则：
- **死亡有代价** — 失去上次存档后的所有进度
- **手动存档** — 不给自动存档的安全网，玩家自己决定什么时候"保存"进度
- **继承机制是未来** — 角色切换/继承据点留到后续 Phase

---

## 二、玩家死亡

### 死法

| 死因 | 触发 |
|------|------|
| HP 归零（战斗/意外） | 伤害致死 |
| 失血致死 | Blood 归零 |
| 丧尸化 | Infection 阈值 → 恶化过程结束 |
| 饥饿/口渴致死 | Hunger/Thirst 归零持续 HP 流失 |

### 死亡处理

```
角色死亡
  │
  ├── 死亡画面（短黑屏 + 死因文字）
  │    "你死于失血过多。"
  │    "你被丧尸咬伤，感染而死。"
  │
  ├── 按钮选择：
  │    [读取最近存档]  [返回主菜单]
  │
  └── 读取存档 → 从存档点继续
```

## 三、存档系统

### 存档方式

| 方式 | 说明 |
|------|------|
| 手动存档 | 暂停菜单 → "保存游戏"。任何时候可存（战斗中不行？） |
| 据点自动存档 | 可选：每次返回据点时自动存档一次（安全网） |

### 存档内容

保存游戏完整状态：
- 角色位置、属性、装备、背包
- NPC 状态（位置、属性、工作指派）
- 据点建筑状态
- 科技解锁进度
- 世界时间/天数
- 地图物品状态

### 读档

- 主菜单 → "继续游戏" → 读取最近存档
- 死亡画面 → "读取最近存档"
- 暂停菜单 → "加载存档" → 选择存档槽

### 存档槽

- A测做 1 个自动槽 + 3 个手动槽
- 存档显示：游戏天数、据点名称、角色名、时间戳

## 四、NPC 死亡

NPC 死亡是**永久损失**（无法通过读档恢复，除非玩家选择读档回到 NPC 死之前）。

### 损失内容

- 该 NPC 的所有熟练度永久丢失
- 该 NPC 携带的所有物品（可被搜刮回收）
- 据点减少一人

### 连锁影响

- 高熟练度 NPC 死亡 → 对应工作线效率断崖下降
- 唯一医生 NPC 死亡 → 伤病治疗能力丧失（直到招募新医生）
- 多个 NPC 连续死亡 → 据点运转瘫痪

### 玩家选择

NPC 死亡后，玩家面临抉择：
- 接受损失，继续游戏（失去一个 NPC 和她的技能）
- 读档回到 NPC 死之前（失去这段时间的所有进度）

## 五、NPC 控制（Rimworld 式）

存活期间，玩家可以在据点内对 NPC 下达指令：

| 指令 | 说明 |
|------|------|
| 征召 | NPC 跟随玩家，参与战斗 |
| 工作指派 | 指定 NPC 去特定工作点（农田/建造/烹饪） |
| 移动 | 点击地面让 NPC 移动到指定位置 |
| 取消 | 取消当前指令，NPC 恢复自主 AI |

- 玩家不直接"切换控制"NPC（不是切换角色操作 NPC）
- NPC 在据点外时依靠自主 AI，玩家通过指令间接管理
- 据点外的 NPC（探索/采集）行为由 AI 驱动

## 六、未来：继承机制（Phase 12+）

当前不做，但设计思路预留：

```
玩家死亡 →
  检查是否有存活 NPC
  ├── 有 → 选择一名 NPC 接管（继承据点、科技、仓库）
  └── 无 → Game Over

继承：
  ✅ 据点建筑、科技进度、仓库物品
  ❌ 死亡角色的熟练度和个人属性
  ❌ 死亡角色的携带物品（留在尸体上，可回收）
```
