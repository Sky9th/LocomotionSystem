# Mod 系统 — 社区创作支撑

**定位**：让玩家从消费者变成创作者。Mod 是游戏的"第二生命"——不靠官方更新，靠社区让游戏永远不死。

---

## 一、核心设计原则

| 原则 | 说明 |
|------|------|
| **零代码门槛** | JSON 数据 Mod 不需要编程。改数值、加物品——文本编辑器即可。对于想写代码的 Mod 作者，C# Mod 也开放（但 API 标记为 unstable，可能在正式版前变动） |
| **官方工具即创作工具** | 策划用的配表工具就是 Mod 作者的创作工具。没有"内部版"和"公开版"的区别 |
| **社区内容一等公民** | Mod 内容与官方内容在同一套系统中运作，不受限制、不被打标、不降级 |
| **渐进复杂度** | 改一个数值 5 分钟，加一件武器 30 分钟，做一个 Total Conversion 需要投入——但每一步都有文档 |

---

## 二、Mod 能做什么

### 2.1 内容创作

| 类别 | 说明 | 示例 |
|------|------|------|
| **物品与装备** | 新增武器、防具、工具、消耗品，定义其属性与效果 | "武士刀 Mod"：新增一把高伤害近战武器 |
| **实体与 NPC** | 新增敌人类型、NPC 模板、动物 | "变异丧尸包"：新增 5 种特殊堕者 |
| **技能与 Ability** | 新增武器技能、套路、天赋树 | "居合术"：为刀类武器新增一套技能组 |
| **科技与配方** | 新增科技树节点、制作配方 | "火药制作"：新增弹药制作科技线 |
| **建筑与设施** | 新增建筑类型、工作台、防御工事 | "瞭望塔"：新增高耐久狙击点建筑 |

### 2.2 数值调整

| 类别 | 说明 |
|------|------|
| **平衡性调整** | 修改武器伤害、耐久消耗、掉落概率等数值参数 |
| **难度定制** | 调整尸潮频率、堕者属性、生存指标消耗速率 |
| **成长曲线** | 修改熟练度升级阈值、科技解锁条件 |

### 2.3 表现与叙事

| 类别 | 说明 |
|------|------|
| **本地化** | 为游戏添加新语言翻译（已有社区翻译架构支撑） |
| **UI 主题** | 替换 UI 配色、字体、布局（未来） |
| **对话与事件** | 新增 NPC 对话、随机事件、任务（未来） |

### 2.4 合集与 Total Conversion

- **Mod 合集**：将多个 Mod 打包为一个兼容合集，统一版本管理
- **Total Conversion**：全面改造游戏世界——新的设定、新的物品体系、新的科技线。**这是 Mod 生态的终极形态，正常需要 5-7 年社区积累才可能出现（参考 RimWorld、Terraria）。不在当前开发路线图中，但架构不封死这条路。**

## 三、创作者工作流

### 入门（5 分钟）
```
打开文本编辑器 → 复制示例 JSON → 修改数值 → 放入 Mods/ 文件夹 → 启动游戏
```
- 不需要 Unity，不需要编程，一个记事本就够了

### 进阶（编辑器辅助，未来支持）
```
游戏内物品编辑器 → 可视化配表 → 一键导出为 Mod
```
- 与策划使用同一套编辑器工具。**此功能不在首发版本中——等 Mod 社区有真实需求后再评估优先级。**

### 深度（代码 Mod）
```
Visual Studio / Rider → 写 C# 代码 → 编译 DLL → 放入 Mods/ 文件夹
```
- 支持使用与游戏相同的语言（C#）编写自定义逻辑，无需额外学习脚本语言
- API 在 pre-1.0 阶段标记为 **unstable**——Mod 可能随游戏更新而失效
- 正式版发布后逐步锁定 API

## 四、分发与发现

### 4.1 分发渠道

| 渠道 | 说明 |
|------|------|
| **Steam Workshop** | 一键订阅，自动下载和更新，是主要分发渠道 |
| **手动安装** | 下载 JSON 文件放入 `Mods/` 文件夹，适用于非 Steam 版本或开发测试 |
| **GitHub / 社区论坛** | Mod 源码托管、版本管理、协作开发 |

### 4.2 游戏内 Mod 管理

- 主菜单 "Mod 管理" 面板
- 查看已安装 Mod 列表（名称、版本、作者、启用状态）
- 启用/禁用单个 Mod
- 调整 Mod 加载顺序（拖拽排序）
- 冲突检测提示（多个 Mod 修改同一内容时高亮警告）

### 4.3 Steam Workshop 集成

- 游戏内上传：Mod 管理面板 → "发布到 Workshop" → 填写描述和标签
- 自动更新：订阅的 Mod 有更新时自动下载
- 合集支持：玩家可创建 "推荐 Mod 合集" 供他人一键订阅

## 五、对游戏生态的影响

### 5.1 延长游戏寿命

Mod 社区是单机游戏的生命线。参考《 RimWorld 》——发布近十年仍在 Steam 热销榜，核心驱动力就是 Mod 社区。一个玩家通关后，Mod 让她回来再玩 100 小时。

### 5.2 社区驱动的平衡

Mod 作者可以快速响应玩家反馈——官方调整一个数值可能需要排期，社区今晚就能出一个 "平衡补丁 Mod"。官方可以从优秀的社区平衡方案中吸收经验。

### 5.3 官方内容的孵化器

表现优异的 Mod 可以被官方收编（在征得作者同意的前提下），成为正式内容的一部分。这给了 Mod 作者向上的动力。

### 5.4 降低内容创作门槛

不是每个玩家都想做 Mod，但想做的人不应该被技术门槛挡在外面。JSON 文件 + 文档 + 示例 = 任何人只要愿意花时间就能创作。

## 六、与其他系统的关系

| 系统 | Mod 的影响 |
|------|-----------|
| **物品/装备** | Mod 可新增物品类型，官方物品表是 Mod 的基线和模板 |
| **实体/NPC** | Mod 可新增敌人和 NPC，使用与官方相同的 PropertyTree 定义 |
| **技能/Ability** | Mod 可新增 Ability 和 AbilityTree，与官方技能共存 |
| **科技树** | Mod 可在官方科技树上嫁接新节点，也可提供全新科技线 |
| **建造** | Mod 可新增建筑类型（使用官方建材） |
| **本地化** | Mod 可直接提供 `community/` 翻译文件 |
| **平衡性** | Mod 可覆写官方数值，玩家自行选择难度/平衡方案 |

## 七、设计决策记录

| 决策 | 原因 |
|------|------|
| JSON 数据 Mod 是第一优先级 | 零门槛：文本编辑器即可创作，覆盖 80%+ Mod 需求 |
| C# 代码 Mod 门开着但不承诺 | 通过 HybridCLR 运行时支持外部 C# 程序集，API 标注 pre-1.0 unstable |
| JSON 格式而非二进制 | 可读：文本编辑器即可打开，降低创作门槛 |
| 与策划工具同一 Schema | 一致：官方数据怎么定义，Mod 就怎么定义，没有"两套标准" |
| Last Write Wins 冲突策略 | 简单：后加载覆盖前加载，玩家通过排序控制优先级 |
| 初期不做 AssetBundle Mod | 务实：先让玩家能改数值加物品，模型/音效后续再做 |
