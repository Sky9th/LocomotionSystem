# v0.6.4 — GameplayTag 提升至 L1_Core + SO 定义层

## 背景

GameplayTag 对标 UE GAS 的 `FGameplayTag`，是**全系统通用基础设施**（战斗、AI、伤病、物品、建造、任务等），不应局限于 L4_Combat。趁零消费者搬迁到 L1_Core，同时引入 `GameplayTagDefinitionSO` 做设计时层级管理（父子引用，改父自动级联）。

## 改动

### 新增
- `L1_Core/GameplayTag/GameplayTag.cs` — struct: +`Depth` O(1)、+`IsAncestorOf`/`IsDescendantOf`、+`Matches(GameplayTag)` 重载
- `L1_Core/GameplayTag/GameplayTagContainer.cs` — sealed class: +类型安全重载、+`HasTagExact`、+`HasTagAtDepth`/`MaxDepthUnder`
- `L1_Core/GameplayTag/GameplayTagDefinitionSO.cs` — [SO] 父子引用 + implicit operator GameplayTag、OnEnable 缓存、OnValidate 刷新

### 删除
- `L4_Combat/GameplayTag.cs` — 搬迁至 L1_Core
- `L4_Combat/GameplayTagContainer.cs` — 同上

### 技术文档
- `gameplay-tag.md` — 更新 L1 路径、namespace、新增 Depth/IsAncestorOf/隐式转换/GameplayTagDefinitionSO 说明
- `gameplay-tag-container.md` — 更新 L1 路径、新增 HasTagExact/HasTagAtDepth/MaxDepthUnder 文档
- `tech/L1-core/gameplay-tag.md` — 新建 L1 基础设施索引文档

### 计划
- `so-cleanup.md` — SO 资产与菜单整理计划（20 个 SO 类菜单路径统一 + 资产目录重组）

## 设计决策

| 决策 | 原因 |
|------|------|
| 设计时 SO + 运行时 struct 双层 | SO 负责编辑器组织与重命名安全，struct 负责 HashSet 存储性能 |
| SO 父子引用（非字符串副本） | 改父 leafName → 所有子孙 FullTag 自动级联更新 |
| `implicit operator GameplayTag` | `SkillDefSO.cooldownTag` 用 SO 引用，运行时自动转 struct，调用侧无感 |
| `Depth` 构造时预计算 | O(1) 层级深度查询，无运行时 GC |
| `HasTagExact`（非层级匹配） | 冷却标签 "Skill.Cooldown.Slash" 不应匹配 "Skill.Cooldown.Slash.Extra" |
| namespace `RedDust.Core` | 与 L1 现有类型同 namespace，全系统直接 using |
